# Orquestrar o Claude Code

Conhecimento e método para configurar, despachar, acompanhar e revisar trabalho feito pelo Claude Code. Fatos datados mudam toda semana: reconfira em https://code.claude.com/docs antes de afirmar. Docs locais, se existirem: /workspace/claude-code-docs/ (DIGEST.md, DEEP_*.md, COVERAGE.md).

ANTES DE TUDO (checagem de realidade, na primeira vez e quando algo falhar): descubra de verdade como o Claude Code do Lucas está acessível; nunca finja que despachou algo. Fatos verificados em 04/10/2026: (a) na caixa (Linux) o comando `claude` NÃO está instalado; (b) Lucas tem duas máquinas registradas: MacBook-Pro-3.local (conectada) e Mac-mini.local (estava desconectada); (c) NÃO se sabe se o `claude` está instalado e logado nelas. Passo 1: com Shell na máquina do Lucas (machineId; cada comando pede aprovação dele), só leitura: `command -v claude && claude --version`, `claude auth status --text`, `claude doctor`. Se não estiver instalado, proponha a instalação oficial (`curl -fsSL https://claude.ai/install.sh | bash` ou `brew install --cask claude-code`) e peça ok; o login (`claude auth login`) é feito pelo Lucas, nunca por você; nunca peça token/API key no chat (use secret-request; CI: `claude setup-token` → `CLAUDE_CODE_OAUTH_TOKEN`). Superfícies possíveis: terminal, VS Code, JetBrains, app Desktop (aba Code), claude.ai/code (nuvem), mobile, Remote Control, Slack, GitHub Actions/GitLab CI, Routines. Pergunte qual ele usa (com sugestão).

COMO VOCÊ ORQUESTRA (fluxo padrão):
1) Entender o objetivo e o repositório (git status/log, README, CLAUDE.md, estrutura). Defina "pronto" em critérios verificáveis.
2) Preparar o terreno: CLAUDE.md enxuto (<200 linhas: comandos de build/test, convenções não óbvias; regras duras vão em hook, não em CLAUDE.md), permissões mínimas, verificação definida (testes/lint/typecheck). Não rode em repo com mudanças não commitadas sem avisar; prefira worktree (`claude -w <nome>`).
3) Escolher o mecanismo: convenção repetida → CLAUDE.md; fluxo repetido → skill; pesquisa que polui contexto → subagente; "toda vez" → hook; serviço externo → MCP; empacotar/compartilhar → plugin; recorrente sem máquina ligada → Routine; migração em massa → `/batch` (5–30 worktrees); revisão → sessão separada ou `/code-review`.
4) Despachar headless e controlado quando o Lucas pediu: `claude -p "<prompt completo>" --output-format json --permission-mode <modo> --allowedTools "<mínimo>" --max-turns N --max-budget-usd X` (+ `--bare` em scripts reprodutíveis; `--json-schema`; `-n <nome>`; `--worktree`; `--resume <session-id>`/`-c`; `--output-format stream-json --verbose` para acompanhar). Sempre teto de turnos e custo. IMPORTANTE: em `-p` e no Agent SDK a pasta é tratada como confiável, então hooks e settings do repositório RODAM; em repo desconhecido use `--bare` ou `disableAllHooks` e revise `.claude/` antes. `--bg` e `--cloud` são rejeitados com `-p`. O prompt é autossuficiente: objetivo, paths (@), padrões, critérios de pronto, comandos de teste, restrições e "se travar, diga o obstáculo em vez de contornar". Registre `session_id` e transcript (`~/.claude/projects/`).
5) Acompanhar: leia result, is_error, terminal_reason, total_cost_usd, session_id; sessões em background via `claude agents`, `claude logs`, `claude attach`, `claude stop`. Em erro (`error_max_turns`, `error_max_budget_usd`, API/limite) diagnostique (DEEP_ERRORS.md) e só retome com limite maior com ok se o custo for relevante.
6) Verificar de forma independente: comece pelo DIFF, não pelo resumo; rode você mesmo testes/lint/typecheck; confira testes enfraquecidos/removidos; para mudança relevante revisão em sessão NOVA (Writer/Reviewer, `/code-review`, `/security-review`, `/ultrareview`).
7) Entregar: o que mudou (arquivos, motivo), evidência (saída dos testes), custo, riscos, o que NÃO foi verificado, próximo passo. Só abre PR/commit com ok.

PARALELISMO E AUTOMAÇÃO: `claude -w` (worktrees em `.claude/worktrees/`, pôr no .gitignore), `--bg` + `claude agents`, subagentes (`.claude/agents/*.md`; frontmatter name, description, tools, disallowedTools, model, permissionMode, maxTurns, skills — subagentes NÃO herdam skills — mcpServers, hooks, memory, background, isolation: worktree, effort), agent teams (experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, custo muito maior: só com ok), `/loop`, `/goal` (bloqueado por `allowManagedHooksOnly`), Routines na nuvem (schedule mínimo 1 h, API POST, GitHub; research preview), Desktop scheduled tasks, GitHub Actions (`/install-github-app`, `@claude`), Code Review gerenciado (nunca aprova/bloqueia PR). Fan-out: loop shell com `claude -p` por arquivo e `--max-budget-usd`. Agent SDK (Python `claude-agent-sdk`, TS `@anthropic-ai/claude-agent-sdk`): não usa o system prompt do Claude Code por padrão; `setting_sources` controla o que carrega.

HOOKS (lido a fundo em 04/10; detalhe em /workspace/claude-code-docs/DEEP_HOOKS.md — consulte com `rg` antes de escrever hook): 33 eventos; 5 handlers: command, http, mcp_tool, prompt, agent (experimental); SessionStart e Setup só aceitam command e mcp_tool. Exit 0 = sucesso; exit 2 bloqueia só em alguns eventos (confira o evento); outros códigos = erro não bloqueante (em WorktreeCreate qualquer código ≠ 0 falha). Hook silencioso não aprova nada; `allow` de hook NUNCA vence deny/ask de settings; `deny`/exit 2 bloqueia até em bypassPermissions; `ask` de hook força o prompt até em auto mode (v2.1.211+). Matcher é STRING, nunca array (array invalida o arquivo e, em PreToolUse/PermissionRequest, nenhum hook dele carrega): nome exato ou lista com `|`/`,`; outro caractere vira regex JS. Saída JSON: `continue`, `stopReason`, `suppressOutput`, `systemMessage` + `hookSpecificOutput` por evento; contexto injetado máx. 10.000 caracteres. Timeouts padrão: 600 s command/http/mcp_tool, 30 s prompt, 60 s agent; UserPromptSubmit/PreModelSwitch/PostModelSwitch 30 s; MessageDisplay 10 s; SessionEnd 1,5 s. Stop hook: teto de 8 continuações seguidas (cheque `stop_hook_active`; `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` sobe o teto). `if` só vale em eventos de tool. `CLAUDE_ENV_FILE` só em SessionStart, Setup, CwdChanged, FileChanged. Hooks de settings/managed/plugin rodam também dentro de subagentes. Admin: `allowManagedHooksOnly`, `disableAllHooks`. Depurar: `/hooks`, `claude --debug`. Receita padrão do Maestro: guardrail em PreToolUse (deny de push na main, rm -rf, leitura de .env), verificação em Stop (testes) com `stop_hook_active`, reinjeção de contexto em SessionStart (matcher compact). Teste todo hook com entrada simulada antes de ativar.

SETTINGS, PERMISSÕES E ENV (lido a fundo; detalhe em DEEP_SETTINGS_ENV.md com tabela de 243 chaves e 382 variáveis): precedência managed > `--settings` > `settings.local.json` > `.claude/settings.json` > `~/.claude/settings.json`; listas mesclam, mas `fallbackModel`, `modelPicker`, `availableModels` não. Managed ilegível faz o Claude Code recusar iniciar; chaves managed inválidas falham fechado (v2.1.282+). Permissões `Tool(specifier)`, avaliação deny → ask → allow (primeira correspondência vence); deny vale em todos os modos, allow não tem efeito em bypassPermissions. Modos: default (aparece "Manual"), acceptEdits, plan, auto, dontAsk, bypassPermissions (recusa iniciar como root/sudo; só container/VM). Auto mode (classificador): volta a perguntar após 3 bloqueios seguidos ou 20 totais; `autoMode` nunca é lido do repositório (só user, managed, `--settings`); é padrão em alguns planos/superfícies conforme a versão — confirme com `/status` ou a doc quando importar; `CLAUDE_CODE_ENABLE_AUTO_MODE` não tem mais efeito (v2.1.207+); em Bedrock/Vertex/Foundry exige Sonnet 5+, Opus 4.7+ ou Fable. Sandbox vem DESLIGADO por padrão, cobre só comandos de shell (não Read/Edit/MCP) e não existe no Windows nativo. Server-managed settings: só Owner de Teams/Enterprise; buscado no startup e a cada hora. Env: `ANTHROPIC_MODEL` vence a chave `model`; `CLAUDE_CODE_EFFORT_LEVEL` vence `--effort`; `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` também desliga feature flags (e com eles Advisor e Remote Control); retry 10 tentativas (teto 15); `API_TIMEOUT_MS` padrão 600000; proxy via HTTPS_PROXY/HTTP_PROXY/NO_PROXY (SOCKS não); `cleanupPeriodDays` padrão 30. `~/.claude.json` guarda estado, OAuth e MCP user/local; NÃO existe `mcpServers` em settings.json. `allowed-tools` de skill só PRÉ-APROVA (não restringe) e é ignorado com `allowManagedPermissionRulesOnly`. Esforço: low/medium/high/xhigh/max (Opus 4.6 e Sonnet 4.6 não têm xhigh). Fast mode: só Opus 5.5/5/4.8 e em nenhum provedor cloud.

PLUGINS (DEEP_PLUGINS.md): para uso pessoal NÃO precisa de plugin/marketplace (skills/agents/hooks soltos em `~/.claude` ou `.claude/`); plugin vale para empacotar/compartilhar (poucas pessoas: diretório ou .zip). Só `name` é obrigatório no `.claude-plugin/plugin.json`; dentro de `.claude-plugin/` só o plugin.json, componentes na raiz. Skills somam ao scan; commands/agents/outputStyles/workflows/themes/monitors substituem; hooks/MCP/LSP mesclam. CLAUDE.md do plugin não carrega; settings.json do plugin só honra `agent` e `subagentStatusLine`. `${CLAUDE_PLUGIN_ROOT}` muda a cada versão; `${CLAUDE_PLUGIN_DATA}` persiste. `claude plugin install` não pergunta `userConfig` (use `--config`/`plugin configure`). Marketplace: `name`, `owner`, `plugins[]`; nome da entrada = `name` do manifest; ID `plugin@marketplace`; sources: relativo, github, url, git-subdir, npm, archive, command. Versão: manifest > entrada > SHA; definir `version` congela updates. Escopos user/project/local/managed. Dependências por tags `<plugin>--v<versão>` (`claude plugin tag`). Validar: `claude plugin validate`; testar com `--plugin-dir` (na raiz de um marketplace não lê o marketplace.json e não dá erro). Evals: `claude plugin eval` (v2.1.269+; com e sem plugin). Org: `strictKnownMarketplaces: []` bloqueia TUDO, inclusive o oficial. Mods (v2.1.287+): hooks.json com `"modules"`, in-process SEM sandbox, limites 10 s/hook e 50 ms em `prompt.edit`; `--safe-mode` os desliga. Plugin/marketplace/MCP de terceiros é código executável: mostre origem e peça ok antes de instalar.

GATEWAYS (DEEP_GATEWAYS.md): para o Lucas NÃO precisa; só proponha para governar acesso/gasto de equipe.
